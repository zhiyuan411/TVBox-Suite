# 设置页配置项功能梳理

> 范围：`设置` 页面（`ModelSettingFragment`）及其 3 个子弹窗（播放器设置 / 搜索性能 / 按钮位置）的全部配置项。
> 方法：静态代码审查（布局 → 点击处理 → 落库 key → 消费点），未运行任何脚本或编译。
> 代码位置均为工程内相对路径。

---

## 0. 总览

| 层次 | 文件 |
|---|---|
| 页面布局 | `app/src/main/res/layout/fragment_model.xml`（另有 `layout-v21/fragment_model.xml` 副本，内容等价） |
| 页面逻辑 | `app/src/main/java/com/github/tvbox/osc/ui/fragment/ModelSettingFragment.java` |
| 播放器设置弹窗 | `ui/dialog/MediaSettingDialog.java` + `res/layout/dialog_media_setting.xml` |

| 弹窗基类 | `ui/dialog/BaseDialog.java` |
| 配置 key 定义 | `app/src/main/java/com/github/tvbox/osc/util/HawkConfig.java` |
| 默认值写入 | `app/src/main/java/com/github/tvbox/osc/base/App.java` → `initParams()` |
| 存储介质 | Hawk（底层 SharedPreferences `Hawk2`），`App.java:210` 初始化 |

**统一的数据流（三类角色）：**

```
fragment_model.xml(布局, id)            ← 只负责"长什么样、点哪里"
        │  setOnClickListener
ModelSettingFragment.java               ← 读 Hawk 填当前值(text)、点击弹选择框、写 Hawk
        │  Hawk.put(HawkConfig.XXX)
HawkConfig.java (key 常量 & getter/putter)
        │  Hawk.get(HawkConfig.XXX)
各业务模块（ApiConfig / PlayerHelper / OkGoHelper / HomeActivity …）← 真正改变行为
```

**页面分组**（由布局中的三个分组标题决定）：

- `llHomeSettings`（文案 `act_home` = "首页"）：左列
- `llPlayerSettings`（文案 `act_player` = "播放器"）：右列（与"首页"同处一个两列网格）
- `llSystemSettings`（文案 `act_system` = "系统"）：占满整行，下方为两列网格

### 1.1 调试模式 `llDebug` / `tvDebugOpen`

**消费点（改变行为的真实位置）：**

- `util/OkGoHelper.java:183`（及 `:72`、`:140`）：调试开启时 OkHttp 日志级别设为 `BODY`，否则 `NONE`。**OkGoHelper 在进程启动时初始化，故此项对网络日志的实际影响需冷启动后才完整生效。**
- `ui/fragment/PlayFragment.java:1894`、`:2077` / `ui/activity/PlayActivity.java:2005` 等：嗅探 WebView 尺寸（调试态 800×400，否则 1×1）。
- `ui/fragment/PlayFragment.java:1917`、`:2096`：`setBlockNetworkImage(!debug)`，非调试态屏蔽嗅探 WebView 的图片加载。
- `util/FileUtils.java:150`：按调试态走不同分支。

> ⚠️ **注意**：`App.initParams()`（`App.java:211`）在**每次冷启动**都会无条件执行 `Hawk.put(HawkConfig.DEBUG_OPEN, false)`，即调试开关**不会跨进程重启保留**（关掉 App 再开就恢复为"关闭"）。这是有意为之的"防误开"，但容易让使用者误以为开关失灵。

## 8. 已发现的细节与潜在问题（供对照学习）

1. **`DEBUG_OPEN` 每次冷启动被强制复位**：`App.java:211` 无条件 `Hawk.put(DEBUG_OPEN, false)`，调试开关无法跨重启保留。
2. **两处 toggle 的显示/读取缺省值不一致**：`HOME_SHOW_SOURCE`（`ModelSettingFragment.java:116` 用 false，`:268` 用 true）、`HOME_DEFAULT_SHOW`（`:144` 用 false，`:819` 用 true）。正常流程因 `putDefault` 存在而无感，但属隐性不一致。
3. **`llHomeIcon` / `llMediaSetting` 不回显当前值**，仅显示 `>`（按钮位置项、播放器设置项）。
4. **README 的「默认设置」代码片段曾经过时**（已修正）：旧内容写的是 `HOME_REC=2 / HOME_NUM=2 / SEARCH_VIEW=2 / DOH_URL=2`，而 `App.java` 实际为 `HOME_REC=1 / HOME_NUM=4 / SEARCH_VIEW=1 / DOH_URL=0`，且旧片段缺少 `BACKGROUND_PLAY_TYPE`、`PLAY_SCALE`、`HOME_SEARCH_POSITION` 等项。现已同步为与 `App.java:208-232` 一致。
5. **`App.java:223` 注释陈旧**：把第三方播放器写成 3=MX/4=Reex/5=Kodi，实际代码与 UI 使用 10/11/12。
6. **`ExoRendererMode` 处于"半下线"状态**：`strings.xml` 中 `media_content_tag_ExoPlayer` / `media_content_ExoPlayer` 的该项被注释，UI 不展示；但 `HawkUtils`/`MediaSettingEnum`/`ExoMediaPlayer` 仍保留完整读写逻辑。
7. **`SEARCH_VIEW` 的 `SelectDialog` 默认选中位置**直接取 `Hawk.get(SEARCH_VIEW, 0)`（`ModelSettingFragment.java:660`），而选项列表只有 `[0,1]`；若历史库中存在 `2`（旧默认）则初始选中位置可能越界，建议后续核对 `SelectDialog.setSelectedPosition` 是否做了 clamp。
8. **`MediaSettingDialog` 对数组长度不一致做了防御**（`MediaSettingDialog.java:115-120`）：文案数组与 tag 数组长度不等时按较短的遍历并打警告，避免越界崩溃——修改 `media_content_*` 资源时需同步 `media_content_tag_*`。
9. **重置与备份的存储位置**：备份在 `外存/tvbox_backup/`，其它 App 卸载不一定清理；重置只清 `lib` 之外的私有目录与外置 App 目录。
10. **`PLAY_RENDER` 对 Exo 无效**：Exo 固定使用 `PlayerViewRenderViewFactory`（`PlayerHelper.java:37-38、67-69`），渲染方式设置只对 IJK/系统播放器生效。
